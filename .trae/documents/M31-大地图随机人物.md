# M31 大地图随机人物：可见冒险者人口池（M-E）

> 承接路线图 M-E：**39 名可见冒险者（战士/弓手/术师）在城/路上流动、占固定名额、空缺即补、
> 有"个人麻烦"、可对话/交易/雇佣 7 天、死亡送医数日回流或永久离开由新人接替**。
> 与 M-C（大地图可见的"物"：遗构/怪物）相对，本里程碑落大地图可见的"人"。

## 与既有底座的分界

M-E 的冒险者**不是**世界模拟那 1600 名模拟居民（`WorldState.npcs`，抽象人口指数、随城流动、
进 `settle_year` 增龄死亡）。它们是第二套"看得见走在大地图上的人"，与 `WorldSeen` 的怪互为对照。

关键取舍在**派生 vs 落盘**：怪的图纸是纯派生（被清、死了就重排）。但冒险者要"占固定名额、保证
空缺即补、死了送医、走了有人接替"——这些**生命周期状态**必须在结算后与读档后仍然成立，否则
"死亡永久离开由新人接替"无从谈起。因此冒险者殊荣走**持久化名册（world 落盘）+ 派生填充**的混合：
- 名册（谁占了哪个名额、此刻什么状态）落盘 `world.wanderer_roster`，随世界存档；
- 名字/外表/麻烦/落点等细节由种子确定性派生，不落盘（换一段世界时间重派生回同一个人）。

这与此前"NPC 关系、世界记忆随世界落盘、转世不换"的口径一致，而不是 `WorldSeen` 的纯靠种子。

## 目标

1. 大地图派生 39 名可见冒险者（战士/弓手/术师三型），每名占一个固定名额；在城（`CitySpace` 近邻）
   与城际路上（`CONTEXT_ROAD` 途经格）游走，可作为可见标记/近邻交互对象。
2. 名额生命周期：空缺自动补（必补，名册永远满额）；被击杀 → 送医数日（`hospitalUntil`），到时
   回流或（概率）永久离开腾名额由新人接替。
3. 交互：上前对话（揭示这名冒险者的"个人麻烦"，`VIEW_EVENT` 抉择卡片）、交易（复用行商/商铺货池）、
   雇佣 7 天（新契约类型，随从携带、参与战斗，7 天后到期）。
4. 全部走可无头钉测的纯规则层 `WandererPool`；绘制/命中测试走 M21/M24 同套 viewmodel+panel 纯函数。

## 实现步骤

### 1. 规则层 `wanderer_pool.gd`（新建，纯函数）

- `capacities()` → 读 `balance.wanderer.capacity`（39）。
- `fill_spec(world_seed, slot, month)` → 单名额满额态：`{ slot, archetype(warrior/archer/mage如
  按 slot 定 54 型), givenName, familyName, gender, age, troubleId, hireCost }`，全由
  （world_seed ^ slot ^ 纪元盐）确定性派生；名字从 `balance.wanderer.namePool`、麻烦从
  `troubles` 抽。
- `trouble(spec)` → 该冒险者的"个人麻烦"文案（`troubles` 池，条目=一句可观察现象，过 P8 筛）。
- `bucket_place(roster, seenTimeBucket, cities, routes)` → 每名冒险者此刻在小地图的落点
  （在某城某近邻格，或在某段路上某格，或露宿一格的确定性位置），不落盘、随桶挪步——看得见在动。
- `hire_contract(spec, world_seed, seq)` → `{ unitId:"wanderer-<slot>", name, archetype, daysLeft:7, cost }`
  供战斗侧的随从规格复用 `NpcInteractionSystem.follower_combat_spec` 的轮廓。
- 生命周期纯函数：`advance(roster, month, rng)` → 名册前进一趟：级医院到期的回流/永久离开、
  腾出的名额补新（`fill_spec`）、7 天契约续算。

### 2. 世界态：`WorldState` 加 `wanderer_roster`（落盘）

- 新字段 `wanderer_roster: Array`，序列化随世界存档（`to_dict/from_dict`、迁移零步兼容，缺省为空再按
  名册补满）。
- 每条 `{ slot, archetype, name, gender, age, troubleId, status: "roaming"|"hospital", hospitalUntil,
  hireUntilMonth, hiredBy, hireSeq }`。
- 首次/加载时若 `roster.size() < capacity` 用 `WandererPool.fill_spec` 补齐到满额（空缺即补）。

### 3. 世界模拟挂骑扣：`world_sim`

- `bootstrap()`：补满冒险者名册（沿用 `_sync_city_npcs` 的生成入口）。
- `settle_month()`：调 `WandererPool.advance`——住院回流/永久离开腾名额补新、天数契约推进；
  产出 `notableEvents`（"XX 重伤已回，又上了路"/"XX 走了，另一名弓手接替他扛起的名字"等）。
- `settle_year()`：住院深治的到年不清，仍按月判——不在此重复，避免双重推进。

### 4. `main.gd` 接线

- 状态：`_wanderer_roster`（对 `world.wanderer_roster` 的会话镜像，供绘制与交互）。
- 绘制：新增 `_draw_wanderer_markers()`，在 `_draw_map`/城空间房 `viewmodel` 一块儿画冒险者标记
  （比怪更亮的金圆/菱形）；命中测试与 `_seen_node_at` 同套，走上/点选即交互。
- 交互（复用现有 VIEW/抉择卡片）：
  - **对话**（P）：揭示该冒险者的"个人麻烦"（`WandererPool.trouble`），给一条抉择卡片。
  - **交易**（T/商图标）：接入既有货池/商铺交互。
  - **雇佣**：对可雇的冒险者签 7 天契约（新增 `active_hires` 的 `daysLeft` 变体或独立
    `wanderer_hires`），`follower_combat_spec` 复用其战斗规格随从；7 天后到期自动解约回流名册。
- 战斗：冒险者作为可交手的具名人形敌人（`unitId="wanderer-<slot>"`），被击杀 → 状态置
  `hospital`（若被放倒）送医数日、或直接永久离开，随 `WandererPool.advance` 处理回落点。

### 5. 数据：`balance.wanderer`

- `capacity: 39`、`archetypes`（warrior/archer/mage 三类阈值或按 slot 定 54 型）、`namePool`
  （前后缀名遗传学）、`troubles`（个人麻烦文案池，≥ 名额），`hireCost`、`hireDays: 7`、
  `hospitalDays`、`leavePct`（永久离开概率）。

### 6. 测试

- `WandererPool.fill_spec`：同种子同 slot 同月份确定性一致；不同 slot 名不同；名额池够抽。
- `advance`：空缺必补满；住院回流/永久离开 + 腾额补新；`leavePct` 掷后名额仍满。
- `hire_contract`：daysLeft=7、unitId 带 slot；`follower_combat_spec` 能吃下冒险者契约。
- `main` 流程无头（视情形）：走上冒险者触发对话揭示麻烦、签 7 天约、击杀后名册进入送医态。

## 关键取舍（写进技术设计 9.35 节 D-142/D-143）

- **D-142 冒险者名册为什么落盘而非像 `WorldSeen` 纯派生**：怪死了重排、玩家重载回来怪还站满
  大地图，可接受；但"39 名固定名额、空缺即补、送医回流、走了接替"是**持续的生命周期**，若纯派生，
  重载/结算后"谁死了、谁在养伤"全部复位，名额与接替就失效。采用持久名册 + 种子派生细节的混合，
  与 NPC 关系/世界记忆随世界落盘的口径一致，避免引入第三套存档哲学。
- **D-143 冒险者为什么用独立名册而不是塞进 1600 模拟居民**：模拟居民是城市人口指数的具象化、
  随 `settle_year` 增龄死亡、由 `purge/query` 批量管理；冒险者是另一群游离在城际流通、可被玩家
  单独招募/放倒的人。硬塞会污染人口的增减/职业配额逻辑，也让"39 名可见冒险者"的名额数字无从独立
  保障。名册独立，且用 `wanderer-` 前缀的 unitId 与之隔离。
