# M17 隐藏属性事件（善恶值 · 幸运 · 声誉）

> 计划文档 · 里程碑 17
> 依据：《轮回之书-隐藏属性事件脚本》《数值框架》第 3 章、《技术设计文档》现有架构
> 交付物：让三种隐藏属性从"被动累计的数字"升级为"会因行为变化、按阈值触发事件、事件反过来改它们、且留下种子跨世作数"的完整闭环。

---

## 一、现状与缺口

`player_avatar.gd` 已有三字段：

- `karma: int` —— 全局（不分城），初始 0，**无 clamp**
- `luck: int` —— 全局（不分城），初始 0，**无 clamp**
- `city_reputation: Dictionary` —— 每城独立，`set_reputation` 已钳到 `REPUTATION_MIN/MAX`（-100~+100）

当前它们全部是**被动累计**：委托交付、城市事件分支、走私查抄时增减。没有任何一处"按隐藏属性阈值**主动弹出**事件"；`karma` 连效果落实点都没有（只有记录意义）；`luck` 已参与掉落命中与回避，但无濒死豁免、无 clamp、无名目上的档位判定。

规格文档共定义三大类 11 个事件（圣职者试炼 / 天使注视 / 深渊招揽 / 恶灵缠身 / 幸运日奇遇 / 厄运连锁 / 占卜者预言 / 授荣誉市民 / 全城通缉 / 冤案 / 特赦）。其中大部分依赖尚未实现的内容（神殿区域、天使事件级战斗、深渊教团暗线、锚点 NPC 互动的具体形态），若全套照做会把里程碑撑成不可测的庞然大物。

**M17 的定位**：不追求把 11 个事件全部落地，而是把"隐藏属性事件"这条**管线**立起来——阈值判定、触发时机、分支预览、后果应用、种子落写全部走通，并挑选三类各一个**不依赖外在未实现设施**的代表事件端到端跑通，让后续事件脚本只需加数据、不用改管线。

---

## 二、范围

### 2.1 做（End-to-End 闭环）

1. **三属性规则层**：`karma`/`luck` 补 clamp（-100~+100），新增统一读写入口与**档位判定**（善/恶、吉/凶、友好/中立/敌对的区间函数），对齐 `city_reputation` 已有的写法。
2. **隐藏属性事件管线**：新规则层 `HiddenAttributeEventSystem`——按"触发判定（属性阈值 + 位置/时机 + 冷却 + 种子）→ 分支预览 → 后果应用（改隐藏属性 + 城市六维/世界标记 + 种子 → 事件流 + 纪年可选）"整条走通，复用 `EventSystem` 的分支-预览-应用模式与 `city_event` 面板骨架。
3. **三个代表事件端到端**：
   - 善恶正向：**圣职者的试炼**（善恶 ≥ +60，进城时有神殿的城市）——负分支写"神殿追讨"种子可激活负向事件。
   - 善恶负向/幸运：**厄运连锁**（幸运 ≤ -60，主动可打断），接"扛到底触底回升 +10"，以及可选的"去神殿祈福 +20"分支。
   - 声誉：**授予荣誉市民**（某城声誉 ≥ +80）——接受/谦辞/索要三分支，声望联动既有城市态度。
   每个事件都带"属性阈值 → 触发 → 分支 → 后果改隐藏属性 → 种子 → 事件流"。
4. **转生"业"**：极端善恶/高价幸运给下一世开局留下事件种子（善业引助缘、恶业招仇家），经 `soul_record`/转生回调挂到新一世。结合数值框架 3.4 的口径。
5. **三处挂钩**：`karma`/`luck` 遇结算不越界；`luck` 落一个效果点（若时间许可，加濒死豁免"幸运 ×N 概率 1 HP 存活"，与战斗结算衔接）。
6. **界面**：隐藏属性仍**不上常规面板**（数值框架 3 节明确由 NPC 态度与事件选项间接感知）——但事件走既有的事件流/钟声横幅，分支走既有抉择面板形态，玩家"被世界记着"看得见。

### 2.2 不做（本轮不膨胀）

- 天使注视（事件级战斗 + 主线暗线线索）、占卜者预言、冤案、特赦、恶灵缠身等留后续里程碑——它们依赖的内容（主线/锚点 NPC 互动深度）尚未就位。
- 神殿区域寻路、深渊教团暗线、锚点 NPC 专属对话树。
- 不新增第二个常驻面板/视图（复用 `VIEW_EVENT` 的抉择形态，不新开 view）。

## 三、数据与配置（`balance.json` 增补）

新增 `hiddenAttrs` 配置段，集中可调项，避免行为硬编码进代码：

```json
"hiddenAttrs": {
  "min": -100, "max": 100,
  "karmaThresh": {"blessed": 60, "cursed": -60, "angel": 80, "haunted": -80},
  "luckThresh": {"fortunate": 60, "unlucky": -60},
  "renownThresh": {"honor": 80, "wanted": -70, "reconcile": 0},
  "eventActiveMonths": 24,
  "karmaEventsCooldown": 6,
  "blessedLuckBp": 250
}
```

事件脚本本身走数据文件描述（阈值/分支/后果），复用既有 `events.json` 的模板形态或新建专用于隐藏属性事件的描述块——实现时以最小改动为准，优先复用 `event_system` 已接受的 `changes/reputation/karma/luck/flags` 后果字段。

## 四、规则层设计

### 4.1 `hidden_attribute_system.gd`（新）

- `class_name HiddenAttributeSystem`，`extends RefCounted`。
- 职责：`karma_score/luck_score/reputation_score` 统一读写并 **clamp**；`band(value, thresh)` 档位判定；评估"是否触发某隐藏事件"（`evaluate(avatar, world, context) -> 可触发的候选`）。
- 保持纯函数 + 就地改 avatar/world 的写法，返回 `{ok, error}` 与 `{ok, event, entry}` 统一形状，能被无头验收测试钉住。

### 4.2 触发时机（接入既有钩子）

| 时机 | 挂钩点 | 说明 |
|------|--------|------|
| 进城 | 玩家走进城市的那一帧（地图/城市面板切换） | 判定声誉、善恶类的"进城/进神殿"事件 |
| 过夜/推进 | 时间推进、野外停留 | 判定幸运类的"夜"事件（厄运连锁） |
| 主动 | 与既有操作并列的一个检查点 | 占卜、祈福类留待后续，本轮以进城/推进两条为主 |

触发频率受 `eventActiveMonths` 冷却与"是否已有同类活动事件"约束，杜绝快进十年连环弹窗。

### 4.3 分支与后果

复用 `EventSystem.branch_preview / outcome_of / effect_label` 的既有模式：每个可触发事件产出 `branches`（2–3 条，后果互斥、允许拒绝不触发心理惩罚的选项），应用后果走统一入口，把隐藏属性增减、城市维度、世界标记种子一并落账，并写进事件流（与委托/城市事件同一条底栏）。

### 4.4 转生"业"

- `karma` 极端（≥+80 / ≤-80，或按配置阈值）或 `luck` 高价，在转生回调里向新一世的 `legacy`/`world_flags` 写入一条"业"标记（善业/恶业/气运）。
- 新一世上场时，由触发检查读到该标记，可激活一个开局助缘/仇家事件（本轮先落到"写标记 + 开局一次提示"的最小形态，不展开暗线）。

## 五、界面

- 不新增常驻面板。事件触发走**既有 `VIEW_EVENT` 抉择形态**：剧情文本在左、分支在右，回车执行 / 点分支执行，ESC 或返回地图可弃。
- 隐藏属性数值不上角色面板——但当一个事件因属性阈值被触发时，事件流与抉择文案会"侧写"出玩家当前的善恶/气运/名声走向（"你的灵魂带着光" "/" 你浑身笼罩着不祥"），让玩家从后果反推出自己站到了哪一档。
- 右上按钮沿用既有「再想想/返回地图」。

## 六、测试（`test_suite.gd` 增补）

全量测试从当前 2105 项出发，新增约 30+ 断言覆盖：

1. **clamp**：karma/luck 越界（±120）被钳回 ±100；声誉已有 clamp 不改。
2. **档位判定**：阈值边界的含/不含（≥ 计入高档、恰为 60 是否触发）。
3. **触发判定**：达标阈值且冷却到点才触发；不达标 / 冷却未到 / 已有同类活动事件不触发；快进十年不连环弹窗（冷却生效）。
4. **分支预览应用**：选分支后隐藏属性增减、城市维度、世界标记种子三者一致落账；弃选项不改属性只关事件。
5. **转生业**：极端善恶/高价幸运在转生回调写出"业"标记；新一世能读到。
6. **事件流**：触发与抉择都写进世界事件流；纪年（若接入）可选写入。
