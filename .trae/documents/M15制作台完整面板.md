# 里程碑 15：制作台完整面板（M14 收口）

## Context（为什么做）

M14 生产技能系统已落地规则层（`Crafting`/`Gathering`）与纯视图层（`CraftingViewModel.build`），但交互上只接了**低风险**的野外采集（地图按 F），**制作台完整面板入口未接**——这是 M14 计划里明确留给后续的收口项。用户选定本模块方向 = **制作台完整面板**：把已有的 [crafting_view_model.gd](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/ui/crafting_view_model.gd)（它已能产出配方行 / 门槛 / 材料 / 产物档位）接到主场景，成为**可操作**的制作界面。

探索确认现状：`main.gd` 有 10 个视图（`VIEW_MAP..VIEW_ENCOUNTER`），绘制走 `_draw()` 按 `view` match 派发到各 `*Panel.draw`，面板绘制与命中测试共用布局函数（"画在这里、点在那里"不会发生）。`Crafting`/`Gathering` 是 `RefCounted` 规则层，`Craft` 返回 `{ok,error,produced,gainedSkills,...}`；`CraftingViewModel.build(crafting, avatar, lookups, cursor)` 返回 `{rows, gather, craftRarity}`。制作台面板应**仿 TradePanel**：它是唯一"行列表 + 右列明细 + 页脚一句说明 + 回车执行"的面板，正好是制作台需要的形状——但它读的是 `_trade_view`，需要一份**自己的** view（`_crafting_view`）与一个 `CraftingPanel`。

## 设计决策（沿用 M14，不新增规则）

1. **入口 = 地图 `V` 键**（新增），对仗野外采集的 `F`；制作台不占用城市面板既有按钮，避免动 `CityPanel`/`CityViewModel`/城市 hit-test 多处联调。制作需要"有化身 + ContentLoader 已装载"，与其它视图一致。
2. **面板仿 TradePanel**：新建 `CraftingPanel`（`draw`/`hit_test`/`buttons`），左列 = 配方行（点击/光标高亮），右列 = 选中配方的门槛 / 材料清单（缺多少）/ 产物与档位，页脚说明。与 TradePanel 同构但读 `CraftingViewModel.build` 的产物。
3. **回车执行**：
   - `kind=craft` 行：直接 `_crafting.craft(avatar, recipe_id)`。
   - `kind=enchant` 行：需要目标实例。**M15 简式规则**：回车时在背包里自动挑**第一件** `appliesTo` 匹配的实例作为目标（无则拒："背包里没有可附魔的X"），附魔成功把词条写进该件并耗尘。不做"从背包挑目标"的次级界面——先跑通附魔链路，细粒度的目标选择留后续。
   - 采集区（`kind=gather` 行）：回车走已封装的 `_gather_action()`（野外采集时已在用，制作台里复用同一动作）。
   - 均参照 `_gather_action`（main.gd:3274）的 ok/error 反馈写 `_status`。
4. **`crafting_view_model.build` 增补 `selected`**（cursor 指向的配方行/采集行的明细），供右列绘制——与 `_trade_view` 的 `selected` 形状一致。这是向后兼容的键增补，M14 现有测试只断言 `rows/gather/craftRarity`，不受影响。
5. **附魔目标在 `_refresh_crafting` 时一并算出**：为每张 enchant 配方的行加 `hasTarget`/`targetName`（背包里可否附、挑中谁），右列与置灰据此显示。规则层不加字段——目标选择是表现层对背包的一次只读扫描（走 `item_instances`+`inventory`，判定 `category == appliesTo`）。
