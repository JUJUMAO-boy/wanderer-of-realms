# M23 副本与商人内容深度

## Context
M21 立起了"随机副本 + 地图商人"两套已测规则层，M22 补齐了战斗手感。但当前"副本为何值得钻"仍单薄——只有地板/宝箱/敌人/下潜，商人收价也只按基准、不问词缀/强化/耐久。M23 顺着用户的候选方向，把副本与商人补出深度：**副本每 5 层出主题特殊层、商人有随机喜好与专属传说货、商人收价接入即时估值**。三者都只改既有层，不新增 class_name（复用 Dungeon / Merchant / ItemInstance），规则层纯函数可无头测、数值全进 balance.json、不落盘。

铁律：规则层纯函数化可无头测；数值全进 balance；能派生不落盘；不重复造公式（复用 ItemInstance.price_bonus / durability）；新 class_name 才需先 --import（本轮无）。交付顺序：规则层 → 视图模型 build → 面板/主场景接线 → 补测试 → 文档+本地提交（提交后询问是否推送，不主动推）。

## A. 副本主题层（每 5 层特殊层）
**theme 只做"文本 + 数量倍率"，不改几何**——walkable/step/连通性都不动。
- `game/src/core/dungeon.gd`
  - 常量 `THEME_EVERY = 5`。
  - `static func theme_for(seed_key, depth, theme_cfg) -> Dictionary`：返回 `{ hasTheme, id, label, hasSupply, treasureMult, enemyMult }`。触发 `(depth+1) % every == 0`；分组 g 用 `DeterministicRNG((hash ^ g*16777619) & 0xFFFFFFFF)` 从 `theme_cfg.themes` 挑一条；非特殊层返回 `{hasTheme:false, treasureMult:1.0, enemyMult:1.0}`。
  - `layout(...)` 读 `opts.theme`，产出 `out["theme"]`；treasure/enemy 数量 `range_int` 后 `roundi(×multi)` 并 clamp 到现有下限。
- `game/src/ui/dungeon_view_model.gd`：`build` 返回加 `"theme"` 与 `"themeLabel"`。
- `game/src/ui/dungeon_panel.gd`：`_ui_header` subtitle 追加主题 label（空则退回原格式）。
- `game/scenes/main.gd`：`_enter_dungeon` 与 `_dungeon_descend` 两处 `Dungeon.layout` 传 `{"theme": ...}`（取 balance.dungeon 的 theme 段）。
- `balance.json` dungeon 段加：`themeEvery:5`、`themeTreasureMult:1.5`、`themeEnemyMult:1.2`、`themes:[{id:outpost,label:小镇哨站,hasSupply:true},{id:treasure_room,label:宝藏房,hasSupply:false}]`。
- 可选回报：清怪后补给站（`_dungeon_supply_ready`=theme.hasSupply，打完最后一只敌回满 HP）——标记可选，核心是主题文本与数量倍率。

## B. 商人随机喜好 + 专属传说货
- `game/src/core/merchant.gd`
  - 字段 `_items: ItemInstance`、`_fav_category`、`_rare_bias`、`_legendary_template`；`create()` 里 `_items = ItemInstance.create_from_config()`。
  - `stock_for` 开头 `_derive_persona()`：按 `favCategoryWeights` 抽喜好类、按 `rareBiasChanceBp` 掷偏稀有、置 `_legendary_template`。
  - 货架偏置：喜好类先占位；`_rare_bias` 时同 category 内优先稀有 ≥rare 模板。
  - 专属传说货：末尾若 `_legendary_template` 不在 `_stock`，强制 append 并用 `legendaryBuyRatio` 报价。
  - `func persona() -> Dictionary`：返回 `{ favCategory, favCategoryLabel, rareBias, sellMultiplier }`。
- `game/src/ui/merchant_view_model.gd`：买侧 hint/标题带人格文案。
- `balance.json` merchant 段加：`sellRatio:0.5`、`favCategoryWeights:{weapon:1,armor:1,consumable:1}`、`rareBiasChanceBp:3000`、`favSellMultiplier:1.25`、`legendaryTemplateId:"weapon_talisman_legendary"`、`legendaryBuyRatio:2.5`。
- `items.json` 新增 `weapon_talisman_legendary`（category 必须在 Merchant.STOCK_CATEGORIES，rarity=legendary，`merchantLegendary:true`）。

## C. 商人收价接入即时估值（核心取舍：不绑城市）
- 抽不绑城市的静态估值，**不**给 `Economy.get_price` 传"中性城市"（五个因子强绑 City，伪造污染字段）。
- `game/src/core/merchant.gd` 新增：
  - `static func instance_base(instance, items) -> int`：`tpl_price + items.price_bonus(instance)`（复用与 Economy 同口径的词缀+强化折价）。
  - `static func durability_factor(instance, items) -> float`：`clampf(items.durability(instance)/items.durability_max(), 0, 1)`。
  - `func buy_back_value(instance) -> int`：`maxi(1, roundi(base × durability_factor × _effective_sell_ratio(category)))`。
  - `func _effective_sell_ratio(category) -> float`：`sellRatio`，喜好类再 ×`favSellMultiplier`。
- `game/src/ui/merchant_view_model.gd` `_build_sell`：用 `merchant.buy_back_value(instance)` 替代固定比例收价（保留旧公式兜底）。
- 进价三工具：词缀/强化→`price_bonus`；耐久→耐久比线性折价；收价比例→sellRatio（喜好类加乘）。
- main.gd 无需额外改动：`_merchant_confirm` 卖出已付视图模型算好的 `price`。

## 交付顺序
1. 规则层：dungeon.gd（theme）→ merchant.gd（persona/legendary/instance_base/durability_factor/buy_back_value/_items）。
2. 视图模型：dungeon_view_model（themeLabel）、merchant_view_model（人格文案 + 卖侧即时估值）。
3. 面板/接线：dungeon_panel subtitle → main.gd 两处 layout 传 theme、（可选）补给站。merchant 人格进提示。
4. 补测试（test_suite.gd M21 块后挂）：`_test_dungeon_theme`、`_test_dungeon_theme_det`、`_test_merchant_persona`、`_test_merchant_legendary`、`_test_merchant_buy_back_value`。
5. 文档（README 里程碑 23 行 + 技术设计 9.27 节）+ 本地提交（提交后问是否推送）。
