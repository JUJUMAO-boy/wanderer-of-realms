# 里程碑 M34｜怪物变体与捕捉（M-F）

> 里程碑：M34（承接 M29 `DungeonBoss`/`DungeonModifiers` 的书名号先例与 M-C 可见窝点，落地 M-F）
> 基线：M33 之后全量回归 3394（通过 0 失败）；HEAD `541ac6b`
> 铁则：能派生就不落盘；规则层纯函数可无头钉测；新 `class_name` 先 `--import` 再跑全量回归；数值全走 `balance`；一次会话现象留场景。变体/捕捉均**不落盘**，由世界种子⊕遭遇/副本会话种子派生（路线图「四」第 1 条默认口径）。

## 0. 先说结论：M-F 把「怪」变成两件看得见摸得着的事

此前（M-D/M29）只有副本最下层那头《书名号》巨兽是"变体"——野外遭遇与副本中层遇到的怪都是白板生物表里抽的普通个体，且打死了只能捡尸体，**不能收**。M-F 从两个方向把"怪"做活：

- **A 怪物变体**：野外遭遇 / 副本中层在出生时有概率摇成《书名号》命名单体——×1.25/×1.67 的书名号档，以及更稀有的 ×2–5「修正」破格档。名字包书名号、四维按倍率放大、威胁略抬一档。既是数值惊喜，也顺带划出捕捉的第一道红线（有声名的东西收不得）。
- **B 捕捉**：兜里揣一只「收容笼」，在战斗中把它掷向**残血**的对手——低血掷、等级上限、生灵/有名/神性拒收，失败至少吃两条代价（笼子毁 + 兽被激怒反扑）。成功则那具身体变成一只「收容的猎物」物件进背包（收藏/战利品）。

设计口径与既有规则层一致：`MonsterVariant` / `MonsterCapture` 都是**纯函数可无头钉测**的新 `class_name`，只读 `balance.monsters` 段与传入的对手/随机源，不碰 `WorldState` 持久化、无副作用，机械后果（扣笼、入包、落标记、激怒反击）由 main 调用方的胶水在战斗里就地结清。

## 1. Feature A｜怪物变体（MONSTER VARIANT）

**现状缺口**：变体先例只有 `DungeonBoss.boss_spec` 一处（最下层固定《》×2），野外与副本中层完全没有"变体"这个概念：
`EncounterSystem._monster_profile`（[encounter_system.gd:354](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/core/encounter_system.gd#L354)）与 `main._dungeon_monster_spec`（[main.gd:4981](file:///c:/Users/YUJINYU/Desktop/侠客游/game/scenes/main.gd#L4981)）都直接取生物表原值，名字不包书名号。

**方案**：新建 `MonsterVariant` 规则层（`monster_variant.gd`，`class_name MonsterVariant`，纯静态函数）。

1. `roll(base: Dictionary, rng: DeterministicRNG, rules: Dictionary) -> Dictionary`
   - 读 `balance.monsters.variant` 段。
   - 先掷 `variantChanceBp`（基点）决定是否变体；命中后按 `tiers`（每档 `{id,label,mult,weightBp}`）权重挑一档：
     - 书名号档 ×1.25 / ×1.67（常见 ~ 稀有）；「修正」档 ×2–5（极稀有，`mult` 落 2.0..5.0）。
   - 返回 `{ isVariant, label, mult, name(base包《》), threatBump }`。非变体返回 `{isVariant:false, mult:1.0}`。
2. `apply(base, roll, extraMult: float = 1.0) -> Dictionary`
   - 产出变体对手：名字包书名号、`hp/attack/armor/magicResist` 按 `mult`（再叠传入的 `extraMult`，供副本修正词条 `enemyStrengthMult` 复用）、`threatLevel` + `threatBump`，并打 `isVariant:true` 标记（供捕捉拒收、掉落偏置）。
3. 接线：
   - `EncounterSystem._monster_profile`：每只出生后调 `roll`，命中则 `apply` 再并入 profile。
   - `main._dungeon_monster_spec`：同类处理，但把 `_dungeon_modifiers.enemyStrengthMult` 作为 `extraMult` 传进去（变体倍率 × 修正词条倍率叠加）。

**验收**：`roll` 同种子恒一致；`apply` 数值按倍率放大且名字包书名号；非变体倍率为 1 不改数值；变体 `isVariant` 真（可被捕捉拒收）。

## 2. Feature B｜捕捉（MONSTER CAPTURE）

**现状缺口**：`Combat` 的 `DOWNED_CAPTURE`（[combat.gd:831](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/core/combat.gd#L831)）是"打倒在地后俘虏 NPC"，对象是**人**、时机是**倒地后**、不需要收容装置。而 M-F 的捕捉是**对怪兽低血投掷收容笼**，机制完全不同，且无任何收容物品概念。

### 2.1 收容装置（物品）

`items.json` 新增两只模板：
- `consumable_capture_cage`「收容笼」，category `consumable`、subtype `cage`、rarity `common`、中等 `price`。普通商铺照 `is_available`（[economy.gd:360](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/core/economy.gd#L360)）即可买到（development ≥ 0）。
- `creature_caged`「囚笼」category `creature`，作为**捕捉成功的容器物件**：实例的 `modifiers` 里记录 {monsterId, displayName, variant, threatLevel}，玩家背包里多一件可留存/回收的收藏。

### 2.2 规则层 `MonsterCapture`（`monster_capture.gd`，`class_name MonsterCapture`，纯静态）

读 `balance.monsters.capture` 段。全部输入=对手 dict + rules + 可选 rng，可无头断言：

1. `is_capturable(unit, rules) -> String`（空串=可收，否则拒收理由，**四道红线**）：
   - 生灵/对话体：`unit.isNpc` 或 category 为 `humanoid` → "生灵有言语，收不进笼"。
   - 有名：`unit.isVariant` 或名字带《》 → "有声名的东西收不得"。
   - 神性：`unit.divine` → "神性不容纳"。
   - 等级上限：`unit.threatLevel > rules.captureMaxThreatLevel` → "它太凶，笼子装不下"。
2. `low_hp_threshold_ratio(rules) -> float`：低于这条 HP 占比才"低血够格"投掷（否则该动作在目标界面置灰并说明"它还有气力"）。
3. `chance_bp(unit, rules) -> int`：低血投掷成功率，基点 0–10000。`baseBp` 起，按「缺口越多越容易」线性抬：`baseBp + (1 − hp/maxHp) × perMissingRatioBp`，钳上限；TL 越高再按 `perThreatPenaltyBp` 递减。
4. `attempt(unit, rules, rng) -> Dictionary`：
   - `{ok, captured, chanceBp, rollBp, consequences:[...], reason}`。
   - 成功 `consequences: []`；失败 **consequences 恒 ≥2 条**：`["deviceLost", "enrage"]`（笼毁 + 兽被激怒反扑）。
5. `contained_item(unit, instanceId) -> Dictionary`：产出 `creature_caged` 实例 `{templateId, modifiers:{kind:"captured_monster", monsterId, displayName, variant, threatLevel}}`，供 main 入包。

### 2.3 战斗动作 + 视图 + 主场景接线

- **`combat.gd`**：新增动作 `ACTION_CAPTURE = "capture_toss"`（[combat.gd:191](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/core/combat.gd#L191) 的 action 分发处）：校验目标在 `captureThrowRange` 内、非倒地/阵亡、`captureApCost` 行动点够；扣 AP、`target["captured"]=true + handled + capturedBy`、写标记 `combat.capture.<unitId>`、入 log。**它只做机械标记，成败判断交给 main**——与 `_do_downed_choice` 的 DOWNED_CAPTURE 同一分工。
- **`combat_view_model.gd`**：`build` 追加可选参 `has_capture_device: bool`；`_main_menu` 在持有笼时追加「捕捉（收容笼）」项 → `MENU_TARGET_UNIT`（pending kind `capture_toss`）；`_target_unit_menu` 对每目标标 `capturable`/低血提示。
- **`main.gd`**：`_combat_confirm`/战斗动作分发处接 `capture_toss`，走 `_do_capture(targetId)`：
  1. 校验 `MonsterCapture.is_capturable`（拒则置灰一口价说明，笼不扣）。
  2. 从背包扣 1 只 `consumable_capture_cage`（`_consume_cage`，就地结账不排队）。
  3. `MonsterCapture.attempt` 用战斗 `rng` 掷。
  4. **成功**：`Combat.capture_toss` 落机械标记 + 移除该单位；`MonsterCapture.contained_item` 经 `_creator.add_item` 入包；`_note_events` 补文案。
  5. **失败**（两条代价）：笼已扣（deviceLost）；`enrage` → 该目标本轮获得一次免费反击（经 `Combat` 对玩家单位打一次，按 `enrageCounterRatio` 缩放伤害，落 log）。
  6. `_refresh` 收尾。

> 收容产物只作收藏/战利品，MVP 不展开饲养/释放；后续如需"役使"再单独里程碑，不在此扩大范围。

**验收**：`is_capturable` 四道红线各自拒收且理由明确；`chance_bp` 残血越高概率越高、超 TL 递减；`attempt` 成功无后果、失败后果恰好 [deviceLost, enrage]；低血够格判定正确。
