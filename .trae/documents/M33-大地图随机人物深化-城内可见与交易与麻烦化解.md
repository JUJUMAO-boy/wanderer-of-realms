# 里程碑 M33｜大地图随机人物深化：城内可见 · 可交易 · 麻烦可化解

> 里程碑：M33（承接 M31 `WandererPool` 与 9.31 一段，深化 M-E）
> 基线：M32 之后全量回归 3363（通过 0 失败）；HEAD `9b8212f`
> 铁则：能派生就不落盘；规则层纯函数可无头钉测；新 `class_name` 先 `--import` 再跑全量回归；数值全走 `balance`；一次会话现象留场景。

## 0. 先说结论：M33 补的是「人是活的可交互的」，不只是地图上的点

M31 把 39 名冒险者画成了大地图上的明黄菱形，走上一位只弹一句「个人麻烦」的**文本**就没了下文：
不识其名面、不能交易、麻烦只是背景板。M33 把这层「人」的接触点做活，三个方向各切一刀：

- **A 城内可见冒险者**：冒险者不再是野外孤魂——进城后在城内网格里也有站定的可见冒险者，走近可互动。
- **B 冒险者交易**：站在冒险者旁能掏钱买他身上带的行货（也能把货卖给他）。
- **C 个人麻烦可化解**：每人那句「个人麻烦」从背景文本变成一笔小的可化解支线——掏一笔钱/回一回面子，麻烦清了，他对你记一份好（雇佣打折 + 一份谢礼）。

设计口径：三者都**复用 M31 的名额身份派生**（`world_seed ⊕ slot ⊕ gen` 确定性），所以「谁在城里、带什么货、欠什么麻烦」都纯派生、不落盘；唯一新增持久化是 **C 的「这份麻烦已化解」标记**（挂在 `(slot,gen)` 上，随世界存档，跟 M31 名册生命周期同一把尺——换了代新人来了，麻烦是新人自己的，标记不算数）。

## 1. Feature A｜城内可见冒险者（CITY VISITORS）

**现状缺口**：`CitySpace.layout`（[city_space.gd](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/core/city_space.gd)）只会摆建筑和 `npc_ids` 躺的居民，城内没有冒险者；进了城就跟 39 名冒险者失联。
`_city_space_interact`（[main.gd:4154](file:///c:/Users/YUJINYU/Desktop/侠客游/game/scenes/main.gd#L4154)）也只处理建筑/居民两类。

**方案**：

1. `WandererPool.city_visitors(world_seed, city_id, bucket, count) -> Array[int]`（新增规则函数、纯派生）：
   - 从 39 个名额里确定性挑 `count` 个「此刻进城歇脚的冒险者」。用 `DeterministicRNG((world_seed ^ city_id.hash() ^ bucket×盐) & 0xFFFFFFFF)` 在水池筛 `count` 个不重复 slot。
   - 「bucket」取地图游荡桶 `_seen_bucket`，与 M31 的地图游荡同一个时间轴——访客身份会随桶滚动，看得见「换了一拨人」。
2. `CitySpace.layout(city_id, building_ids, npc_ids, visitors: Array = [])`（扩展，向后兼容）：
   - 新增常量 `VISITOR_SLOTS`（城里 `y4..10` 空地带的若干固定点，**区别于** `NPC_SLOTS`，绝不压到建筑/居民）。
   - 把传入 `visitors`（slot 数组）摊成 `visitors: [{slot, x, y}]` + `visitor_cell: {"x,y": slot}`。
   - 新增 `CitySpace.near_visitor(layout, pos) -> int`（四邻命中访客返回 slot，否则 -1）。
3. 表现层：
   - `CitySpaceViewModel.build` 追加 `visitors` 中心点清单。
   - `CitySpacePanel.draw` 画访客标记（明黄菱形，与大地图一致），`hit_test` 加 `"visitor"` 分支。
4. 主场景接线：
   - `_enter_city_space` 调 `WandererPool.city_visitors(...)`，把结果并进 `layout` 调用。
   - `_city_space_interact` 加一支：`near_visitor` 命中 → `_open_wanderer(slot, gen)`（见第 4 节广告菜单）。

**验收**：`city_visitors` 同参数恒一致、无重复、落在 [0,39)；`layout` 带 visitors 不破坏既有 building/npc 落位；`near_visitor` 命中可无头钉。

## 2. Feature B｜冒险者交易（WANDERER TRADE）

**现状缺口**：冒险者身上没有「货」的概念——只有 `hireCost` 和 `combat_spec` 用于雇佣。无交易通路。

**方案**：新建 `WandererTrade` 规则层（纯函数、无头可测，借 `CharacterCreation.add_item` 与 `avatar.money`）。

1. `stall(spec, rng) -> Array`：由 `fill_spec` 的 `(slot,gen)` 派生这位冒险者随身带的货，返回 `[{templateId, displayName, unitPrice}]`。
   - 货品从 `balance.wanderer.trade.palette`（若干 `{templateId, weightBp}` 集合）按权重抽 `stockCount` 件。
   - `unitPrice` 用 `Economy.get_price` 的同一套定价（进城同城价），价目表与到手货同种子对得上。
2. `buy(world, spec, goodsIndex, rng) -> {ok, reason, instanceId, displayName, money}`：
   - 校验 `avatar.money ≥ unitPrice`；扣钱；`CharacterCreation.add_item(avatar, templateId, newId, seed)` 落实例。
   - 失败给明确 `reason`（钱不够/没货）。
3. `sell(world, spec, templateId, instanceId) -> {ok, reason, money}`：
   - 从背包取货（复用 Economy 的取货/身上不可卖判定），按 `sellDiscountBp`（如收价七折）付铜。
4. `balance.wanderer.trade`：`{ stockCount, sellDiscountBp, palette: [...] }`。

**UI**：在广告菜单「交易」分支里，`_list_keys` 翻货架，回车买一件；切「卖给他」再翻自己背包卖。买/卖的账当场落（`avatar.money` / `inventory`），不进变更队列——与既有买卖 `_enter_trade` 同一口径（[main.gd:1529](file:///c:/Users/YUJINYU/Desktop/侠客游/game/scenes/main.gd#L1529) 注释可佐证）。

**验收**：`stall` 种子确定；`buy` 钱够扣钱+入包、钱不够拒；`sell` 身上东西拒卖、背包货给折价收回。

## 3. Feature C｜个人麻烦可化解（WANDERER TROUBLE）

**现状缺口**：`balance.wanderer.troubles` 每条只有 `{ id, label, desc }`，`_reveal_wanderer` 只念 label 就完事；麻烦永不可了结。

**方案**：

1. **扩充 `balance.wanderer.troubles`**：每条补可化解结构：
   - `resolveCost`（化解这一桩的价码，正整数铜）
   - `resolveLine`（化解成功后一句观察，过 P8 筛）
   - `rewardCopper`（谢礼铜，通常 < cost）或 `rewardItem`（一件谢礼 templateId）
2. **`WandererTrouble` 规则层**（纯函数）：
   - `resolved(world, slot, gen) -> bool`：查 `world.wanderer_troubles_resolved["slot-gen"]`。
   - `resolve_step(world, spec, trouble) -> {ok, reason | line, rewardCopper | rewardItem, moneyAfter}`：
     - 已化解 → 拒；`avatar.money < resolveCost` → 拒（给 reason）；否则扣钱、掉 `rewardCopper` 或加 `rewardItem`、把 `(slot,gen)` 记进 `wanderer_troubles_resolved`。
   - **化解的红利**：已化解冒险者的 `fill_spec`/`advance` 招募价按 `balance.wanderer.resolveHireDiscountMult`（如 ×0.65）打折——谢礼之外，掏钱把他的麻烦了结换来一段更便宜的雇佣（对应他愿意记你的好，一条生命周期的暗示）。
3. **持久化**：`WorldState` 新增 `wanderer_troubles_resolved`（Dictionary `"slot-gen"->true`），随 `to_dict/from_dict` 走存档（与 `wanderer_roster` 同一模式，序列化键 `wandererTroublesResolved`）。按 `(slot,gen)` 记，避免"换了一代新人还占着上一代的化解"。

**验收**：`resolve_step` 幂等（再化拒）；钱不够拒；化解后 `resolved` 真、钱账对；换 `gen` 不算数。

## 4. 接触点｜城内「冒险者小菜单」（交互胶水）

`_open_wanderer(slot, gen)` 打开一个轻量菜单（进城站着不动才好做买卖），三个选项游标（W/S 或 ↑/↓ 切换，回车确认，ESC 退出）：
- **交谈**：弹一句（优先 `trouble.desc` / 一句派生观察）。
- **交易**：进第 2 节 `WandererTrade` 的买卖。
- **帮忙化解**：进第 3 节 `WandererTrouble.resolve_step`。

大地图上走上的行为**保持 M31 现状**（弹一句揭示文本），不额外开店——人站住才好讲价。菜单只画在城内访客旁，游标与确认逻辑放 main.gd（复用既有 combat 菜单的游标手感，不另派新节点）。
