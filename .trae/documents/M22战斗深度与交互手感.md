# M22 战斗深度与交互手感

## Context（为什么做）

M21「随机副本 + 地图商人」落地后，战斗系统仍是**判定式 + 固定 AI**，与 RogueLike 的"策略手感"有差距；同时用户提出两项操作层痛点：
1. **方向键连按无法持续走路**（地图/城内/副本三处按住方向键只走一格）。
2. **怪物/人物/NPC 没有名字与身份标识**，战斗地图 token 只显示首字符、看不到是谁。

用户已确认 M22 **全做**：两项手感补齐 + 战斗深度（随从AI行动倾向 / 元素连携 / 战场障碍）。

架构分层固定：规则层（RefCounted 纯函数，不碰 WorldState）+ 视图模型（无头可测纯函数）+ 面板（静态 draw/hit_test）+ main.gd（会话接线）。新增 class_name 需先 `--headless -- --import`；全量测试 `--headless -- --test`（当前 2356/2356 绿）。

## A. 方向键按住持续走路

**根因**（已确认）：`game/scenes/main.gd:4335` `if not key_event.pressed or key_event.echo: return` 丢弃所有按住重复事件；地图 `_move`(4881)、城内 `_city_space_step`(3690)、副本 `_dungeon_step`(3862) 都是"按键一次走一格"。地图点击走 `_walk_to`(3503)+`_walk`+`_process`(3567) 动画能持续。

**方案**（改用"按住态"而非依赖 OS 重复）：
- `_unhandled_input`:方向键 `pressed` 时记 `_held_dir`（x,y），release 清空；改为对方向键放行 pressed/release，其余仍按当前 echo-drop 逻辑。
- `_process`(3567):在现地图 `_walk` 分支外，新增各视图按住持续步进计时器（独立字典，勿与 `_walk` 互覆）。
  - 地图：按住 → 沿方向用 `_plot_walk_path` 扩展 `_walk` 路径，复用行走动画与 `_report_walk_stop`(3553)；遭遇只在动画收尾一次 `_encounter_advance(total)`，天然不连打。
  - 城内：按住 → 定时（0.15s）调 `_city_space_step`；副本 → `_dungeon_step`。城内无遭遇、副本按格自理，即时跳格即可（MVP）。
- 松开/切换视图清 `_held_dir`。

**改动**：`main.gd` 的 `_unhandled_input`、`_process`，新增 `_step_held_dir()` 工具函数。

## B. 名字与身份标识

数据源已齐（`encounter_system.gd:354-446` 已带 name/displayName/category/isNpc/npcId），无需新表。

- `combat_view_model.gd:_battlefield`(106) token 增 `displayName/category/creatureKind`；`_unit_rows`(67) 增 `identity`（"名字·类别"）。
- `combat_panel.gd:_draw_unit_token`(278) token 下方 `UiTheme.draw_text_center` 名字小牌；`_draw_side_panel`(299) 名字旁加类别标签；悬停出身份行（复用 `UiTheme` draw_text/button_row）。
- 城内 `city_space_panel` 居民近邻已带 label；`npc_interaction_panel`(188-196) 已显名字/种族——补一句身份/简介即可。
- 新增 `combat_view_model.identityOf(unit)` 纯函数（可无 head 测）。

## C. 战斗深度

### C1 随从 AI 行动倾向
`combat.gd:_build_unit`(285) 透传 `aiTendency`（enemy 缺省 "attack"）。倾向放 main.gd `_append_follower`(2597) 生成 spec + `hire` 数据。`auto_action`(340 附近) 按 `actor.aiTendency` 分流 player 侧：guard（卡玩家前）/ finisher（只补刀低血）/ ranged（保持距离）/ attack（现逻辑）。纯逻辑可测。

### C2 元素连携（最小闭环）
新建 `game/src/core/chain_system.gd`（class_name，**需 --import**；或并入 combat.gd 省导入）。命中且 `element_counter_milli`(632)>0 时攒层，达 `threshold` 触发 `bonusMilli` 加伤并清零。配置入 `balance.json` 新段 `elementChains:{threshold,bonusMilli}`。`combat_view_model` 行加 `chainStacks`，`combat_panel` 侧栏显示。测试断言攒层/触发/清空。

### C3 战场障碍
`combat.gd` 增纯函数 `has_clear_line(a,b)`（Bresenham 过 `obstacles` 表，与 `_do_move` 447/961 同表）。`_do_attack` 远程判定若被遮挡施加命中惩罚或禁用，日志补"被遮挡"。配置开关入 `balance.json` 的 `combat:{losBlock:true}`。视图已画障碍。

## 测试与验收

- 纯函数（C1 倾向决策、C2 chain、C3 has_clear_line、B identityOf）加进 `game/tests/test_suite.gd` 的 `run_all()`，用 `--headless -- --test` 全量回归。
- A 为会话接线，人工验收（地图/城内/副本按住持续走、松开停）。

## 风险规避

- A：`_process` 同时服务 `_walk` 动画与按住步进 → 用独立字典、互不覆盖；地图按住沿用动画收尾判遭遇，杜绝 `_move` 每步连判遭遇。
- C2 若并入 combat.gd 则无新 class_name、免 import；需在 combat 内保持状态与现行 `submit_action` 事务一致。
