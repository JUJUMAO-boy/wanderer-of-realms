# 里程碑 M35｜代神深化：恩惠 · 改信神罚 · 圣物（M-A）

> 里程碑：M35（承接 M25 `GodBlessing` 的祈祷雏形，落地 M-A 三件事）
> 基线：M34 之后全量回归 3439（通过 0 失败）；HEAD `bf1e042`（已推送 origin/main）
> 铁则：能派生就不落盘（虔诚由 karma 派生）；规则层纯函数可无头钉测；新 `class_name` 先 `--import` 再跑全量回归；数值全走 `balance`；一次会话现象留场景。恩惠/改信/圣物的「当前化身持有态」随化身落盘（身体这件皮的事），虔诚本身不落盘（由善恶现算）。

## 0. 先说结论：把"跪下来求一字回音"变成"三件事真的生效"

M25（D-127~D-130）已经把神从"背景板"做成**可祈祷**：P 键开祈祷列表、`GodBlessing` 纯规则层给虔诚（善恶→0..100）、gods.json 四神各带三档恩惠门槛，回车即结算出**一段文案**。但恩惠/代价/神罚**都还只是字**——"行的正，就更少被夜里的手摸走东西"写在卡片上，可玩家照旧夜间被摸；"每次祈祷烧掉一点运气"也不真扣.

M-A（《世界观 v2》§2.3"代神三件事"）要求这三样各从文案变成真实机制，M35 逐个落地：

- **A 恩惠**：不白给——献祭**某样东西**（祭品/时间）换**持续一段**的庇护，而非永久神迹；庇护有真实数值效果、按三档门槛给、到了自然日自动到期（借用 disguise 的"绝对自然日到期"先例）。
- **B 改信神罚**：背一柱投另一柱，**旧圣物"咬"你一口**——跨神改信是"拿走过它一样东西又反悔"的代价，可逆但贵；罚值由当前掌握的圣物数量与改信方向决定。
- **C 圣物**：神的"具体一块"，摸走被咬、献给另一神殿换改信渡让、也是**唯一能跨世带走的硬通货**（转移进灵魂账，转世后回囊中）。

三者延续 M25 的落点习惯：**规则层纯函数**（`Pontiff`/`Relic`）、**数值全走 `balance.deity` 与 `gods.json`**、**化身态（当前恩惠、掌圣物、背柱与否）随化身落盘**、报销时只改化身资产，不碰世界存档。

## 1. Feature A｜恩惠 = 献祭换一段庇护（真实 buff）

**现状缺口**：`GodBlessing.pray_result`（[god_blessing.gd:45](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/core/god_blessing.gd#L45)）只返回 `effect` 字符串与 `cost` 字符串，不产生任何化身变化。`_pray_confirm`（[main.gd:3766](file:///c:/Users/YUJINYU/Desktop/侠客游/game/scenes/main.gd#L3766)）回车后只写一句 `_note_events`，无真实效果。

**方案**：把"恩惠/代价"从字符串升级成**机制字典**，新增 `Pontiff` 规则层（`pontiff.gd`，`class_name Pontiff`，纯静态）。

1. **gods.json 升级恩惠结构**（保持 `displayEffect` 文案给面板，新增结构化字段）：
   ```json
   "blessings": [
     { "threshold": 40, "displayEffect": "行的正，就更少被夜里的手摸走东西。",
       "buff": { "kind": "theft_resist", "value": 30, "days": 3, "tierLabel": "低" } },
     { "threshold": 70, "displayEffect": "守序之人走夜路，脚下更稳。",
       "buff": { "kind": "walk_ease", "value": 1, "days": 4, "tierLabel": "中" } },
     { "threshold": 90, "displayEffect": "它把目光落在你身上，代价都明码标价。",
       "buff": { "kind": "bargain", "value": 8, "days": 5, "tierLabel": "高" } }
   ]
   ```
   四神各三档的 `buff.kind` 各不相同（`theft_resist`/`walk_ease`/`bargain`/`night_vision`/`fire_resist`/`reincarnation_keep`/`sleep_ease`/`warning` 之一），`days` 给"持续一段"，`value` 给量。
2. **cost 升级**（把"烧掉一点运气/折一点沉眠/耗掉一段旅程/献上一点记忆"从文案变成机制）：gods.json 每神加 `sacrifice:{ kind, amount }`——枚举 `karma` / `luck` / `days`（沉眠时间）/ `copper`（把"献点东西"落成钱）。
3. **新增 `Pontiff` 纯规则层**：
   - `behind_of(god, karma) -> bool`：当前善恶低到连最低档都够不着（沿用 cursed 阈值），返回能否献祭强求。
   - `blessing_spec(god, karma, rules) -> Dictionary`：按 `devotion` 定到哪档，返回该档 `buff` 机制字典 + `sacrifice`。
   - `blessing_added(avatar, buff, rules) -> Dictionary`：把庇护登记到化身（有效期 `today + days`），返回 {ok, activeUntilDay, kind, value}。
   - `blessing_active(avatar, kind, today, rules) -> bool` / `blessing_value(avatar, kind, today, rules) -> int`：读化身当前庇护，供实际结算查询。
   - `sacrifice_pay(avatar, sacrifice, rules) -> bool`：扣 `karma/luck/money` 或登记 `days` 占用；代价不够返回 false（祈祷不生效、不落任何账）。
   - `sync(avatar, today, rules)`：每日边界清掉过期的庇护（复用 disguise `sync` 的模式）。
4. **PlayerAvatar 新增化身字段**（随化身落盘，见 `to_dict/from_dict`）：`blessings: Dictionary`（kind -> { value, activeUntilDay }）。
5. **接线**：
   - `main._pray_confirm`：先 `blessing_spec` 拿档位与 `sacrifice` → `sacrifice_pay`（不够则提示"你拿不出它要的"并退回）→ `blessing_added` 记庇护 → 文案展示这次给的是**具体 buff**（"未来 %d 天，夜间失窃概率降 30%"），而非干巴巴的 displayEffect。
   - 每日边界 main 调 `Pontiff.sync` 剥过期庇护（与 `disguise` 同处）。
   - **实际成效挂点**（选 2–3 个最贴 buff 语义的接线，避免空转）：
     - `theft_resist` → `StealGate.success_pct`（夜间有人偷你时，被偷成功概率 -value）；
     - `walk_ease` → 移动推进时少耗一点（复用 `_report_walk_stop` 的小时折算）；
     - `bargain` → 买卖价差里玩家少花/多得一点（`Economy.get_price` 或 merchant 报价侧按 value 减）。
6. **`GodBlessing` 保留兼容**：`pray_result` 仍可被测试引用，但其"不败"部分改由 `Pontiff` 承接；M35 内 `pray_result` 降级为薄包装或在 main 改用 `Pontiff` 后不再调用（测试同步替换），旧 `pray_result` 及其测试若成死代码则删除，不留双轨。

**验收**：无祭品/负代价不生效（`sacrifice_pay` 返回 false）；同种子同档位同 buff；庇护写入化身 `blessings` 且 `sync` 到期剥除；`blessing_value` 在有效期内返回 `value`、期过返 0；至少 `theft_resist` 与 `bargain` 两条真实入口可"看到 buff 在起作用"。

## 2. Feature B｜改信神罚：背一柱投另一柱，旧圣物咬你

**现状缺口**：目前祈祷只对**单柱**生效，无所属概念，谈不上"背一柱投另一柱"；`cost` 里虽有"背叛之火"这类神罚文案，但无真实代价。

**方案**：给化身一个"当前准许/接圣物"的登记，改信时结算神罚。

1. **PlayerAvatar 新增** `accepted_relics: Array[String]`（接过的圣物 godId 列表，随化身落盘）+ `current_patron: String`（当前背的柱，空=无）。
2. **`Pontiff` 规则层新增纯函数**：
   - `convert_cost(god, avatar, coup_target, rules) -> Dictionary`：改信到 `coup_target` 的神罚 = 以 `accepted_relics.size()` 为基准的**逐件咬**（每件 `perRelicPenalty`，可读回既有 `penalty` 文案 + 数值落点：karma 扣、或 money/耐久任一落盘代价），返回 {ok, karmaCost, relicCount, penaltyText, reversible:true, refundCost}。
   - `convert(world, avatar, coup_target, rules, rng) -> Dictionary`：**结算改信**——把 `current_patron` 换成 `coup_target`、把手里（背包 + 已接受）的旧柱圣物"咬一口"（按 `convert_cost` 扣代价）、旧圣物转为"待赎/已拒"态（可逆但贵：回头再 `reconvert` 要再付 `refundCost`）。
   - `revert_cost(...)` / `revert(...)`：可逆路径，付钱换回。
3. **接线**：祈祷列表加一项「改信」——确认时会列出"若转向其它柱，回头两难"的提示与神罚数值；玩家确认才执行 `convert`；改信后旧柱圣物失效（buff 里若有旧柱的持久庇护立刻剥除）。

**验收**：`convert_cost` 的 karmaCost 与 `accepted_relics` 数量正相关；`convert` 真正改写 `current_patron` 并把旧柱庇护同步剥除；`revert` 付 `refundCost` 可换回；多次改信记账但每次都要付。

## 3. Feature C｜圣物：摸走被咬 · 献给别殿 · 跨世硬通货

**现状缺口**：没有任何"圣物"物件。M-B 的乱入者剧本（收债人 6.5）认圣物当抵押，但圣物本身还不存在。

**方案**：在 god_blessing 的纯规则层面补 `Relic` 语义，用现有物品实例承载：

1. **圣物物品模板**：`items.json` 新增 `relic_<godId>`（7 件，四神各一 + 神罚/王权/深航 或按需），category `relic`、rarity `epic`、`relicOf: <godId>`、标注"跨世"。物品实例 `modifiers` 里带 `{relicOf, sigil}`。
2. **`Relic` 规则层**（`relic.gd`，`class_name Relic`，纯静态，读 `balance.deity`）：
   - `snatch_cost(rules) -> int`/`snatch(world, avatar, god, rng) -> Dictionary`：从神殿**摸走**圣物——先被"咬一口"（karma 扣 + 该殿黑名，复用 D-134 `CriminalState`/变装），失败后果由 `balance` 控。
   - `offer(world, avatar, relic, target_god, rules) -> Dictionary`：把一件圣物**献给另一神殿**，换 `current_patron` 转移（改信通道的"渡让"形），同时把那件圣物从背包卸下。
   - `across_lives(avatar, reincarnation) -> Dictionary`：圣物是**唯一可跨世带走的硬通货**——`reincarnation.settle_death`（[reincarnation.gd:340](file:///c:/Users/YUJINYU/Desktop/侠客游/game/src/core/reincarnation.gd#L340)）时把化身背包里 `category=="relic"` 的实例写进 `SoulRecord.relics`，转世 `from_dict` 回囊。
3. **接线**：`SoulRecord` 加 `relics: Array`（序列化往返）；转生清算时过滤 `relic` 类别进灵魂账、重生时写回新化身背包；改信/献祭路径复用 D-134 的黑名单态。

**验收**：摸走圣物有被咬的 karma 代价；献给另一殿确实转移 patron 且把圣物从背包卸下；`settle_death` 把圣物写进 `SoulRecord`、转世回来后仍在新化身背包里；非圣物（category≠relic）不跨世。
