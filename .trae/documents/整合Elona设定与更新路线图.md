# 《轮回之书》整合 Elona 式沙盒设定：更新路线图

> 上游：`elona-setting-prompts.html`（v1.0，2026-09-22，P0–P8 八组设定提示词）
> 目标：把这份提示词包的世界框与机制句法「重新整合」进《轮回之书》，并从**设定文档**起步，给出可执行的更新计划。
> 铁则不变：能派生就不落盘、不迁移存档、规则层纯函数可无头钉测；新 `class_name` 需 `--headless -- --import`，全量回归 `godot --headless --path game -- --test`。

---

## 0. 先说结论：这份包对我们真正新增的是什么

《轮回之书》**已经有**：世界模拟（城市六维/商路/1600 NPC）、M17 善恶·幸运·声誉（≈因果值）、M18 NPC 人格·好感、EncounterSystem 随机遭遇（威胁分层）、M21 副本、M23 商人、转生·沉眠。Elona 包触及的三处真空：

1. **世界框没落地**：神系、纪元/古文明遗构（副本的来源故事）、八原型城镇分工、昼夜·天候（以太风类）、传闻表——这些全在提示词 P1，游戏里散在叙事文案，没进规则。
2. **大地图可见的生物/副本/人物没有**：现在遭遇与副本是"随机事件"，不是地图上看得见、会自己出现的实体（对应你在意的那句「副本像 Elona 一样出现在大地图」）。
3. **机制句法是"正路配后门 + 代价无评价 + 世界不记恨只记代价"**：这个不是单个功能，是贯穿所有交互的审查口径（P2/P3/P8 的骨架）。

路线图的顺序之所以**从设定文档起步**，是因为 P1 定下的地理/纪元/神/时间规则会被 P2 行为、P5 副本、P7 怪物直接引用；先把世界框落成文档，后面每个机制都有同一套"口径真相"可查。

## 二、更新路线图（分阶段，每阶段=一个可验收的里程碑）

### 阶段 0｜设定文档（先从这开始，本次路线图的产出物）

**产出文件**：`docs/世界观与背景设定-v2.md`（在既有上游世界观文档基础上新增以下章节；不破坏现役 cities.json/世界模拟）

1. **四条内核**（改自 P0）：世界不围绕玩家旋转 / 一切代价无道德评判 / 生成优先于编排 / 死亡与损失不可逆——作为后续所有机制的验收口径写进文档首部。
2. **大陆与纪元**（P1.A）：轮回之书的纪元名、上一纪元留下的「遗构」统称与成因（为 M-C 的可见副本埋世界观解释）、以及"为何会突然出现/消失"的故事口径。
3. **神系**（P1.B）：生成 N 位神，每位：关联属性、恩惠三档门槛、祈祷成本收益、改信神罚——数值与既有"业/转生"口径对齐（善恶隐藏属性可承接神的恩惠/惩罚）。
4. **八原型城镇职能**（P1.C）：把现役城市逐一贴上职能原型表（矿业镇/庆典首都/无法治市场/魔法艺术镇/竞技场港/雪村教会/良马农庄/山顶温泉）；标注"罪犯唯一能安全进出的城"与"没有守卫的城"（可承接确信走私线的十字路）。
5. **昼夜·天候**（P1.D）：夜间（19–7 时）犯罪/偷窃更易得手、熟睡 NPC 无察觉；刮 OO 风暴（可命名为既有的某世界事件）时户外移动更快、遭遇混杂更强个体、避难所内时间快+不饿——挂在引导 `_advance`/Clock 钩子。
6. **传闻表**（P1.E）：`rumors.json` 若干条，至少三分之一为假、互相矛盾并存、不标注真假（供事件/同行文案抽取）。
7. **P8 文风审查**：设定文档通篇删主角光环/道德说教/教程腔/终极真相，每 300 字至少一处荒诞细节。

**验收**：文档定稿后，P1.C 的职能原型能逐个映射到现役城市（可核对 balance/cities 数据），P1.D 的怪色与 Clock 刻度兼容，Rumors 抽取能进 VIEW_EVENT 文案。

### 里程碑 M-A｜神系与昼夜天候的**规则层落地**（承接设定文档）

- 新增 `gods.json`（数位神：属性关联/恩惠门槛/祈祷代价/神罚）、`weather.json`（天候窗口前 10 日，风+急降）；`WorldState` 加祈祷/神的派生字段（**能派生则不加存档**）。
- 主场景：祈祷（可复用装饰性事件 VIEW_EVENT）、夜间偷窃修正（接 M17 善恶/幸运）、天候对户外移动与遭遇敌强化的影响。
- 纯函数：`GodBlessing.threshold(devotion)`、`Weather.penalty_on(pos,date)`、`rumors_pool(seed)` 可无头断言。

### 里程碑 M-B｜NPC 行为句法：后门 + 世界记忆（小件，批量补味道）

- 给 P3 的既有通道补"后门"字段：如罪犯变装交易、训练师双币种、复活回收因果值。
- 世界记忆：守卫死后更强重生（接敌人生成）、击杀店主掉神器、因果 ≤ -30 进罪犯态（店主拒卖，无法治城/自宅除外，变装绕过）——接 M17 善恶与声望档位。
- 文案：为每通道写一句"玩家能观察到的现象"，过 P8 筛。

### 里程碑 M-C｜副本与怪物落大地图（核心大件）

> 承接用户原话：副本要像 Elona 一样出现在大地图，怪物在地图上可见、直接打遭遇战。

- **可见副本点**：世界网格派生"副本落点 + 危险度前缀（五档，P5 表 3）+ 主题（八类，表 4）+ 0–2 条修正词条"；副本在 `_draw_map` 绘制为可见标记，走上即进 `_enter_dungeon`；"地壳变动"事件按周期重置全部可见副本（回收生命周期，P5 图 2）。**复用** M21 `Dungeon.layout` + `theme_for`；把现有 `_dungeon_discover_check` 迁移为"可见副本点生成"而非随机遭遇。
- **可见游荡怪物**：地图上派生怪物窝点（危险度→威胁层，复用 `EncounterSystem.tier_at`/`roll` 产怪），窝点内游荡、玩家走进该格触发遭遇战；取代现有"野外每 N 步随机遭遇"的计数器触发（保留进城治安遭遇）。绘制/命中测试走耐 M21 同套 viewmodel+panel 纯函数。
- **验收**：`WorldSeen.dungeons()`/`monsters()` 派生且种子确定；一把可见副本的重入/消失；一场可见怪物重叠战斗可无头触发。

### 里程碑 M-D｜BOSS 与修正词条（M-C 的纵深）

- 副本最下层 BOSS（书名号标记）、进最下层公告+撤退机会、击杀掉宝石宝箱/尸体/全部装备；修正词条每层叠深；主题决定怪物池与掉落偏向（接 M21 宝箱/敌人）。

### 里程碑 M-E｜大地图随机人物（人口池）

- 39 名可见冒险者（战士/弓手/术师），在城/路上流动、占固定名额、空缺即补、有"个人麻烦"，可对话/交易/雇佣 7 天、死亡送医数日回流或永久离开由新人接替。**量大**，独立里程碑。

### 里程碑 M-F｜怪物变体与捕捉

- 变体标记（书名号 ×1.25/×1.67、修正 ×2–5）接到怪物生成；捕捉需要 收容装置 + 低血量投掷 + 等级上限 + 不能收有名/神性/对话体，失败后果≥2 条。

## 三、落地顺序的建议

1. **阶段 0（设定文档）**——你确认文档骨架后我即撰写 v2 设定文档。
2. **M-C（可见副本/怪物）**——优先级最高，直接回应你对"随机对战斗不符现代、副本要进大地图"的诉求；且能复用 M21/M23 与 EncounterSystem，见效快。
3. **M-A（神系·天候）** 与 **M-B（后门·世界记忆）** 可插空并行——都是小件、纯函数可钉。
4. **M-E（随机人物）**、**M-D（BOSS）**、**M-F（变体/捕捉）** 依次排后，取决于你已经玩到的阶段。

以上节奏随时可拆：先只做设定文档，或先做 M-C 把"大地图可见"跑起来，再回头补神系。

## 四、待确认的三处口径（定了就不会反悔）

1. **怪物变体/可见实体是否落盘**：沿用铁则"由世界种子派生、不落盘"→ 读档后已清怪物/已通关副本会重生成；(选落盘则需存档迁移)。**默认取不落盘**。
2. **"随机遭遇"替换范围**：野外/路面换成可见怪物；进城治安偶发遭遇与"路上商车"保留随机（可选：商人也做成可见货点）。**默认保留城市随机、只改野外可见**。
3. **可见怪物行为档**：先做"窝点内游荡+碰触触发"；"玩家靠近会追击拉怪"作为后续增强。**默认先做碰触档**。
