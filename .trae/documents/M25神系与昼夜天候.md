# M25（M-A）神系与昼夜天候 · 实现计划

## Context（为什么做这个）
路线图阶段 0 设定的四块"世界框真空"中，M-C（大地图可见副本与怪物）已作为 M24 落地并推送。M-A 要补上承上启下的两块**规则层真空**：**神系**与**昼夜·天候**——两者都还没进规则，只散在叙事文案里。

本轮范围（用户已拍板）：
- **4 位神**，gods.json 配置；主场景**地图按一键开"祈祷"列表**（复用 VIEW_EVENT 抉择卡片形态）。
- **天候**：weather.json 配"天候窗口（前 10 日，风+急降）"；**风暴时按确定性倍率放大遭遇对手 hp/attack**（用户选"缩放属性"）。
- **夜间偷窃修正只建接口**：夜间窗口 + 偷窃修正纯函数（接善恶/幸运），**交付给 M-B 的偷窃通道用**（M-B 才做偷窃）。
- 全部纯函数可无头钉测、数值全走 JSON、**能派生就不落盘**（神系不改存档、祈祷结果会话级即时结算）。

## 现状接入点（已探查）
- 时刻派生：`WorldTime.hour` = `tick_in_month % ticksPerDay`（src/core/world_time.gd:28），白天/夜可派生、不落盘。
- 遭遇对手结构携带 `hp / maxHp / attack / weaponAttack`（encounter_system.gd:303-311,367-370）——天候缩放可直接改对手字段。
- 遭遇入口：`_encounter_advance()`（scenes/main.gd:2815 起）目前是"落格命中可见实体"；天候敌强可与可见战斗共用一处后处理。
- 隐藏属性：`HiddenAttributeSystem.read_attr()` 读全局 `karma`/`luck` + 城市 `reputation`（hidden_attribute_system.gd:44-53）——夜间偷窃修正读取它。
- 抉择卡片：VIEW_EVENT 的列表/分支形态（`_refresh_event` main.gd:1226 起）作为"祈祷回向神"的复用骨架。
- 配置：ContentLoader 从 `res://data/` 读 JSON（content_loader.gd:11-29 清单、1049 读、1074 balance 校验）；新 JSON 需在启动清单登记。

## 改动清单

### 1. 数据文件
- **新增 `game/data/gods.json`**：4 位神。每条：`id / name / title / domain`（关联属性名）、`blessings`（三档恩惠：`threshold`(devotion 门槛) + `effect`）、`cost`（祈祷代价，如消耗沉眠/karma）、`penalty`（负表现/改信神罚文案）。
- **新增 `game/data/weather.json`**：天候条目。每条：`id / label / windowDays`（此窗口内生效的连续天数）、`movementCost`（户外移动额外代价）、`enemyMult`（遭遇对手 hp/attack 倍率）、`desc`。至少一条"风暴"（OO 风/急降）。窗口按 world_seed + 当前 day 确定性命中一条（晴空为兜底，`enemyMult=1`、`movementCost=0`）。
- **ContentLoader**：按既有清单方式登记两文件；`get_balance_section` 或新 getter 读取；`_validate_*` 对数字字段做白名单校验（参照 balance 校验，未知键不拒）。

### 2. 纯规则层（新增 class，无头可测）
- **`src/core/god_blessing.gd`（class_name GodBlessing）**
  - `devotion_of(god, karma) -> int`（karma ±100 → devotion 0..100，可派生）
  - `blessing_tier(god, devotion) -> int`（0..3，按 gods.json 的 blessings.threshold）
  - `pray_result(god, karma, rng_seed) -> Dictionary`（{tier, effect, cost, penalty, ok}，确定性；不高则不济/高则恩惠，karma 过低触发 penalty 文案）
- **`src/core/weather.gd`（class_name Weather）**
  - `entry_at(world_seed, day, rules) -> Dictionary`（确定性命中一条天候）
  - `is_night(hour) -> bool`（19–7 时）
  - `enemy_mult(entry) -> float`（≥1）、`movement_cost(entry) -> int`（≥0）
  - `night_steal_modifier(karma, luck, hour) -> int`（**只建接口**：夜间走正加成、白天走负/0；karma 与 luck 各按带宽折算，返回 bp 修正值——交付 M-B，不在此调用）

### 3. 主场景接线（scenes/main.gd）
- **祈祷视图**：新增 `VIEW_PRAYER` 枚举与一路 match 分发；新 `PrayerViewModel`（纯函数 `build(gods, karma, devotion) -> {list/branches}`，复用事件抉择卡片渲染）；地图按一键（拟 `KEY_B`，实现时 grep 确认未占用）开祈祷列表 → 选神 → 确认 → `_settle_pray(result)`（会话级即时结算：给增益文案/状态，或触发神罚文案；**不落存档**）。返回地图用 ESC/导航项。
- **天候接线**：`_encounter_advance` 或其上的可见战斗后处理，读取 `Weather.entry_at`：风暴时对遭遇 `spec.opponents` 的每项 `hp/maxHp/attack` 乘 `enemyMult`（回合级可见敌强）；`movementCost` 并进步数/节奏。
- **入夜提示**：`_advance`/行走时若 `is_night(hour)` 在 `_status` 提示"入夜了"（让夜间窗口可被玩家观察到，且让夜/天候规则不成为死代码）；夜间偷窃修饰函数不在此调用，留 M-B。

### 4. 测试（tests/test_suite.gd，run_all 追加 5–6 组）
- 神系：4 神读取与数量、`devotion_of` 边界、`blessing_tier` 门槛映射、`pray_result` 同种子确定/低 karma 触发 penalty。
- 天候：`entry_at` 同(dur)确定、不同日期可能不同、晴空兜底；`is_night` 边界（18/19/7）；`enemy_mult≥1`、`movement_cost≥0` 钳制；`night_steal_modifier` 夜间正/白昼非正、karma/luck 依赖有界。
- 辅助构造：复用既有 `_new_encounters`/WorldTime 或最小 stub（造 `Rules` 字典 + bare 参数），参考 `_test_world_seen_*` 的 `_seen_built` 模式。
